# Rookie Quest Brand Architecture

## Umbrella brand

**Rookie Quest** is the parent tabletop-gaming brand.

**Core line:** Every legend starts somewhere.

**Four verbs:** Play. Run. Explore. Build.

The word “rookie” is not intended to mean “beginner-only”. It represents the starting point of any new tabletop experience: a first character, a first campaign, a first painted miniature, a first world, or the first session of something completely new.

## Visual identity

The parent brand should feel like a **premium tabletop label**, not a generic fantasy dashboard. The visual system is deliberately restrained so the individual products can carry stronger personalities without making the parent site noisy.

### Parent identity
- Deep midnight navy backgrounds
- Warm antique-gold compass mark and parent-brand accents
- Cinzel for display/brand typography
- Manrope for interface and supporting copy
- Generous spacing and thin dividers instead of heavy panels
- Fantasy atmosphere through typography and symbols rather than overloaded artwork

### Shared compass motif
A simple compass is the core Rookie Quest symbol. It represents the start of a journey and gives Keeper, Forge, Worlds and the future game a shared visual anchor without forcing them to use identical logos.

### Product colours
- **Keeper / Run:** Guild Ledger — ink navy, parchment, brass and wine-seal red
- **Forge / Build:** ember orange
- **Worlds / Explore:** parchment gold
- **The Game / Play:** arcane violet

The colour should identify the product through lines, icons and wordmarks rather than filling entire pages with colour.

### Homepage rule
The parent homepage should stay intentionally minimal:
1. Rookie Quest identity
2. “Every legend starts somewhere.”
3. The four product paths
4. One short explanation of how the ecosystem connects
5. A clear route into Keeper, the live product

Avoid turning the homepage into a long list of features. Product-specific detail belongs on the relevant product page.

## Product family

### Rookie Quest Keeper — Run

Status: **Live / active development**

The digital campaign and character platform. Keeper is the first working part of the ecosystem and remains the primary product while the wider brand grows.

Long-term responsibilities:
- Character creation and character sheets
- Campaign management
- Player and GM workspaces
- Session preparation and live-play tools
- NPCs, locations, quests, handouts, maps and uploads
- Imports from future Rookie Quest Worlds content
- Rules support for the future Rookie Quest game
- Links to relevant Rookie Quest Forge terrain packs

### Rookie Quest Forge — Build

Status: **In development**

The physical/digital terrain line, starting with downloadable files for home 3D printing.

Initial product direction:
- Modular base frames
- Interchangeable floor tiles
- Walls, doors, stairs and pillars
- Stackable elevation pieces
- Railings, balconies and ledges
- Themed textures and scenery
- Storage-friendly stacking
- Encounter-specific printable packs

Future commercial direction:
- Individual STL packs
- Themed environment bundles
- Complete encounter kits
- Adventure-linked Forge packs
- Potential physical printed products later, without making that a requirement now

### Rookie Quest Worlds — Explore

Status: **In development**

The publishing label for original settings, adventures and lore.

Possible content:
- Full campaign settings
- Campaign books
- Standalone adventures
- Cities and regions
- Factions
- Creatures and NPC collections
- Encounter locations
- Lore supplements

Worlds should be system-flexible where practical. Individual settings should be allowed to have their own names and visual identities while still carrying the Rookie Quest Worlds label.

### The Rookie Quest Game — Play

Status: **Future project**

The eventual original tabletop roleplaying system. “The Rookie Quest Game” is a working product label, not necessarily the final system name.

Design principle: do not lock the final rules or name before enough real playtesting exists to justify them.

Desired direction:
- Welcoming to new players without being shallow
- Fast access to meaningful turn choices
- Strong GM support
- Enough depth for long campaigns
- Designed alongside Keeper rather than adapted to it later
- Easy links to Worlds adventures and Forge encounters

## Ecosystem model

The products should strengthen one another instead of behaving like unrelated projects.

Example future flow:

1. A GM discovers or buys an adventure through **Rookie Quest Worlds**.
2. The adventure can be added to **Rookie Quest Keeper**.
3. Keeper imports useful campaign structure such as NPCs, locations, quests and encounter notes.
4. Relevant encounters can point to a matching **Rookie Quest Forge** printable pack.
5. The group can use whatever rules they prefer, or eventually use the original **Rookie Quest game system**.

This relationship is the main strategic advantage of the brand.

## Website structure

Initial routes:
- `/` — Rookie Quest parent-brand hub
- `/keeper` — Rookie Quest Keeper product landing page
- `/forge` — Rookie Quest Forge overview / development page
- `/worlds` — Rookie Quest Worlds overview / development page
- `/game` — future RPG overview / development page

Keeper's authenticated application routes remain unchanged (`/home`, `/characters`, `/campaigns`, etc.) so the brand expansion does not destabilise the working product.

## Commercial roadmap

### Phase 1 — Establish the brand
- Parent Rookie Quest identity
- Keeper presented as the first product
- Forge, Worlds and Game product architecture visible
- Consistent naming and navigation

### Phase 2 — Launch Forge downloads
- Finalise the modular tile specification
- Produce starter packs and test prints
- Define file licences for personal-use purchases
- Add product catalogue, account library and downloads
- Connect selected terrain packs to Keeper encounters

### Phase 3 — Publish Worlds content
- Define the first flagship setting
- Build a repeatable adventure format
- Add digital Keeper imports
- Pair suitable locations/encounters with Forge packs

### Phase 4 — Original system development
- Establish design goals
- Prototype core resolution and character rules
- Run private playtests
- Iterate before naming/finalising the system
- Build native Keeper support alongside development

## Naming rule

Use **Rookie Quest** for the company/umbrella identity.

Use a clear sub-brand only when it explains what the product does:
- Rookie Quest Keeper
- Rookie Quest Forge
- Rookie Quest Worlds

Do not force “Rookie Quest” into the eventual RPG's final title if a stronger standalone system name emerges. The relationship can instead be shown as “A Rookie Quest game”.
