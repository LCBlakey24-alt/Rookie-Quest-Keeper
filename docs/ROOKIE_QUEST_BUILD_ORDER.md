# Rookie Quest build order

Rookie Quest should grow in a deliberate sequence. The public website should only present a product as real when that product has earned it through design, testing and polish.

## Phase 1 — Rookie Quest parent brand

Goal: make the main Rookie Quest website feel complete before multiplying product sites.

Current priorities:
- Finish the parent landing page visual hierarchy, navigation and messaging.
- Keep the Rookie Quest identity consistent: midnight navy, antique gold, restrained fantasy styling and the compass mark.
- Make Keeper unmistakably the first and current product.
- Present Forge, Worlds and the Rookie Quest RPG as a roadmap, not as finished products.
- Keep sign-in and Keeper access obvious from the top navigation.
- Test the parent site on desktop and mobile before expanding the public product structure.

Exit condition: the parent landing page feels intentional and finished, not like a collection of four unfinished microsites.

## Phase 2 — Rookie Quest Keeper

Goal: make Keeper the first fully polished Rookie Quest product.

Work order:
1. Public Keeper landing page and onboarding.
2. Login speed, reliability and first-use flow.
3. Dashboard and navigation consistency.
4. Character creation / character management polish.
5. Campaign creation / campaign management polish.
6. GM tools, live session flow and combat polish.
7. Assessment / specialist tools where relevant.
8. Mobile and tablet pass.
9. Accessibility, empty states, loading states and error handling.
10. Final QA and product copy.

Exit condition: Keeper can stand on its own as a product we are happy to send someone to without explaining unfinished areas first.

## Phase 3 — Rookie Quest Forge

Goal: finish the physical system before building the public store/catalogue around it.

Before public implementation:
- Lock the connector standard through physical test prints.
- Finalise the base grid/frame family.
- Finalise interchangeable floor tiles.
- Finalise walls, doors, stairs, railings and pillars.
- Finalise elevation / multi-level rules.
- Test storage and stacking behaviour.
- Build a complete Starter Set and print it as a real encounter kit.
- Test printer compatibility and minimum build-volume assumptions.
- Photograph/render finished pieces only after they represent the actual product.

Then build the Forge product site, catalogue, printer filters, file library and purchasing/download flow.

Exit condition: Forge has a complete, tested Starter Set that can actually be printed and used at the table.

## Phase 4 — Rookie Quest Worlds

Goal: turn original setting material into a coherent published content line.

Before public implementation:
- Decide the first setting/adventure to publish.
- Establish a repeatable format for lore, locations, NPCs, encounters and adventures.
- Define how Worlds content can import into Keeper.
- Define how specific encounters can reference Forge packs where useful.
- Produce one complete, polished release before building a large catalogue.

Exit condition: one real Rookie Quest world/adventure product exists in a publishable format.

## Phase 5 — Rookie Quest RPG

Goal: create an original tabletop roleplaying game only when the system has a clear reason to exist.

Before public implementation:
- Define design goals from real campaign and Keeper experience.
- Prototype the core resolution system.
- Build and test character creation.
- Test combat, exploration, social play and advancement.
- Run repeated playtests with different groups.
- Revise until the rules are teachable and stable.
- Give the game its final name only once its identity is clear.

Exit condition: a playtested ruleset exists that can support a complete campaign, not just a collection of ideas.

## Public website rule

At any point, the main site may show the roadmap and the direction of Rookie Quest. It should not expose detailed shops, catalogues or product claims for unfinished products simply because the code can be built early.

Current public emphasis:

**Rookie Quest → Keeper → Forge → Worlds → Rookie Quest RPG**

Keeper is first. The rest follows when it is ready.
